1. Add `updateAppBadge()` function in index.html:
   - Guard: `if (!navigator.setAppBadge) return;`
   - Get `myId` from `getMyPlayerId()`, get `ds` from `S.ds`
   - If `ds && ds.started && !ds.complete && myId === ds.order[ds.cp]`: call `navigator.setAppBadge(1).catch(() => {})`
   - Else: call `navigator.clearAppBadge().catch(() => {})`

2. Call `updateAppBadge()` in three places:
   - At the end of the `connectToRoom()` onSnapshot callback (after `render()` on line ~2487) -- this fires on every remote state change
   - At the end of `pickTeam()` (after `render()` on line ~3393) -- clears badge after user picks
   - At the end of `autoPickHighestSeed()` (after `render()` on line ~3549) -- clears badge after auto-pick

3. Add the contextual notification permission prompt. Create `showNotificationPrompt()` function:
   - Guard: if `!('Notification' in window)` return
   - Guard: if `Notification.permission !== 'default'` return (already granted or denied)
   - Guard: if `localStorage.getItem('mm4_notif_dismissed')` return (user previously dismissed)
   - Check iOS standalone mode: `const isIOS = /iPad|iPhone|iPod/.test(navigator.userAgent); const isStandalone = window.matchMedia('(display-mode: standalone)').matches || navigator.standalone;`
   - If `isIOS && !isStandalone`: show a guided overlay with message "To receive notifications, first add this app to your Home Screen using the Share button, then open it from there." with a [Got it] dismiss button. Set `localStorage.setItem('mm4_notif_dismissed', '1')` on dismiss. Return early.
   - Otherwise: show a prompt banner at the top of the app (insert via DOM, not template literal rebuild) with text "Get notified when it's your turn to draft?" and two buttons: [Enable] and [Not now].
   - [Enable] calls `requestNotificationPermission()` (see below), then removes the banner.
   - [Not now] sets `localStorage.setItem('mm4_notif_dismissed', '1')` and removes the banner.

4. Add `requestNotificationPermission()` async function:
   - Call `await Notification.requestPermission()`
   - If `'granted'`: call `await initFCM()`, call `showToast('Notifications enabled!')`, call `updateAppBadge()`
   - If denied: call `showToast('Notifications blocked. You can enable them in browser settings.')`

5. Call `showNotificationPrompt()` at the end of `selfRegister()` (after `render()`) -- this is the contextual moment (user just joined a room). Also call it at the end of `claimPlayer()` for returning players.

6. Add CSS for the notification prompt banner. Style it as a dismissible bar at the top of the app area:
   - Background: `#2a2a44` (matches card bg from design system)
   - Padding: `12px 16px`, border-radius: `8px`, margin: `8px 16px`
   - Flex layout with text on left, buttons on right
   - [Enable] button: gold accent `#C5991A` background, dark text
   - [Not now] link-style button: subtle, no background

7. Update `firestore.rules` to allow the new `fcmTokens` subcollection:
   - Add a match rule inside the `match /rooms/{roomId}` block:
   ```
   match /fcmTokens/{playerId} {
     allow read, write: if true;
   }
   ```
   Note: Since there is no Firebase Auth (sessionless PIN model), we cannot restrict by auth.uid. The data is non-sensitive (FCM tokens are opaque and useless without the server key). Open read/write is acceptable for this friend-group-scale app.

8. Add `initFCM()` call inside `connectToRoom()` onSnapshot callback (after render and updateAppBadge) -- this refreshes the FCM token on every app reconnection, handling token rotation per Pitfall 6 from research. Guard with `if (Notification.permission === 'granted')` to avoid redundant calls.
