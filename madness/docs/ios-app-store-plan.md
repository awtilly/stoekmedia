## 1. Scope and constraints

- **Packaging only.** The web app in `madness/` stays vanilla JS with zero npm dependencies. All
  Capacitor packages live in a separate `madness/ios-app/` directory with its own `package.json`,
  the same way `greendoor/` does on the `app-store-capacitor` branch.
- **Bundle the web code locally** (`webDir`), do not point `server.url` at stoekmedia.com. A remote
  URL is the fastest way to a 4.2 "this is just a website" rejection, and it breaks offline.
- **Firebase stays as-is.** Same project `march-madness-snake-draft`, same Firestore rooms, same
  Cloud Functions. Native push reuses the existing FCM-based functions (section 5).
- **No NCAA marks anywhere store-facing.** See section 2.
- **Toolchain: Xcode 26 on the Mac.** Capacitor 8 requires Xcode 26.0 or later, and since 2026-04-28 App
  Store Connect refuses uploads not built with Xcode 26 / the iOS 26 SDK. Xcode 26 needs macOS 15.6 or later.
  The scaffold's deployment target (iOS 15.0) and `swift-tools-version: 5.9` are fine as they are. Check this
  before the Nov 2026 simulator build; an older Xcode is a hard stop, not a warning (checked 2026-10-26).

## 5. Native push via the existing Cloud Functions (needs Joe for `functions/`)

`functions/index.js` sends **data-only** messages (`{ tokens, data: {...} }`). The web service
worker turns those into notifications. iOS will **not display data-only messages** when the app is
backgrounded. The functions need, for every send:

```js
{
  tokens,
  data: { ...existing },
  notification: { title, body },
  apns: { payload: { aps: { sound: 'default', badge: 1, 'mutable-content': 1 } } },
  webpush: { headers: { Urgency: 'high' } }
}
```

Adding `notification` also changes web behaviour: the browser shows it automatically **and**
`onBackgroundMessage` in `sw.js` still fires, so the web would show two notifications unless
`sw.js` stops calling `showNotification` when `payload.notification` is present. That is a
`sw.js` change plus a `CACHE_NAME` bump: **needs Joe**.

Plugin: `@capacitor-firebase/messaging` (Capawesome). Setup in Xcode: Push Notifications
capability, Background Modes > Remote notifications, `GoogleService-Info.plist` from the Firebase
console, APNs auth key (.p8) uploaded to Firebase > Project settings > Cloud Messaging.

## 6. App Store Review risk register

| Guideline | Risk | Mitigation |
|-----------|------|------------|
| **4.2 Minimum functionality** ("just a website") | High for a wrapped PWA | Bundle locally; native push, haptics, share sheet, app badge, offline cache; splash + app icon; no "open in browser" links. Mention these in Review Notes. |
| 4.2.2 web content | Medium | Do not use `server.url`. Everything in the bundle except Firestore calls and the scores/bracket relay (the `ncaa` Cloud Function). |
| **5.3 Gaming, gambling** | Medium: bracket pools read as betting | App moves no money, has no prizes, no entry fees, no payment links. Say so explicitly in Review Notes and the description ("for fun among friends"). Do not add any "buy-in" wording to the app. |
| 5.1.1 Data collection | Low | Privacy policy URL (section 7). Only name, PIN hash, push token, room data. |
| 2.1 App completeness | Medium: off-season there is no live tournament | Reviewer demo room (section 8) with a completed draft and partially filled bracket. |
| 2.3.8 Metadata | Low | Screenshots must match the app; no NCAA marks. |
| 5.1.1 / privacy manifest (ITMS-91053) | Low (checked 2026-10-26) | The app's own Swift (`AppDelegate`, `SceneDelegate`) calls no required-reason APIs, and Capacitor 8 and the Firebase iOS SDK ship their own `PrivacyInfo.xcprivacy`, so no app-level manifest is required. If a plugin or Swift addition ever touches `UserDefaults`, file timestamps or disk space, add `App/PrivacyInfo.xcprivacy` in Xcode (project uses explicit file references, so it must be added through Xcode, not by dropping a file). Fill the App Store Connect **App Privacy** questionnaire before the first upload: Name, Other User Content (picks, room data), Device ID (push token); not used for tracking; linked to the user only by their own display name. |
| 4.0 Design / iOS feel | Low-Medium | Bottom nav and tap states already exist. Check keyboard does not cover the PIN input. |
| 3.1.1 In-app purchase | None | No purchases. |
| Intellectual property (5.2) | Low (was Medium) | The app shows no team logos since #53; only team names, seeds and records. Nothing to crop out of screenshots. |
