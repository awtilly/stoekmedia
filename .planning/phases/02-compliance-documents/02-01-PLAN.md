Create `functions/index.js` with two callable Cloud Functions:

**1. createSenderIdentity (onCall):**
- Validates caller is authenticated (context.auth required)
- Reads the caller's Firestore profile from `users/{uid}` to get fullName and email
- If Firestore email is missing, falls back to `context.auth.token.email` (BSND-04)
- Calls BoldSign Sender Identity API: `POST https://api.boldsign.com/v1/senderIdentities/create` with `{ name: fullName, email: senderEmail }` using `X-API-KEY` header from `process.env.BOLDSIGN_API_KEY`
- On success, writes `boldSignSenderIdentityStatus: "pending_approval"` and `boldSignSenderEmail: senderEmail` to `users/{uid}` Firestore doc
- Returns `{ status: "pending_approval", email: senderEmail, message: "Check your email to approve the sender identity" }`
- On BoldSign API error, throws HttpsError with details
- If sender identity already exists (boldSignSenderIdentityStatus is "approved" in Firestore), skip creation and return `{ status: "already_approved" }`

**2. sendComplianceDoc (onCall) -- SHELL ONLY for now:**
- Validates caller is authenticated
- Accepts `{ templateId, clientId, listingId }` as data parameters
- Reads caller's Firestore profile to get sender email for `onBehalfOf`
- Uses fallback chain: `userDoc.email || context.auth.token.email` (BSND-03, BSND-04)
- Checks `boldSignSenderIdentityStatus` -- if not "approved", log a warning but proceed without `onBehalfOf` (graceful degradation)
- Returns `{ status: "not_implemented", message: "Send flow will be implemented in Plan 02-03" }` as placeholder
- Comment block documenting where Plan 02-03 will add: template lookup, merge field resolution, BoldSign API call, complianceDocs write
