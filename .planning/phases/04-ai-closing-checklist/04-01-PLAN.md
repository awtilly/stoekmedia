**2. MO_CLOSING_CHECKLIST_TEMPLATE constant array:**
Build the complete Missouri residential closing checklist template as specified in the research document's "Missouri Closing Checklist Template Content" section. Each item has:
```javascript
{
  id: "snake_case_id",           // Deterministic ID for Firestore doc
  task: "Human-readable task",   // Display text
  category: "pre_contract",      // One of the three categories
  transactionSide: "buyer",      // "buyer" | "seller" | "both"
  propertyTypes: ["SFH", ...],   // Which property types this applies to
  linkedTemplateId: "mo-xxx",    // Maps to documentTemplates ID or null for non-doc items
  deadlineOffsetDays: null,      // Days relative to closing date (negative = before, null = no deadline)
  sortOrder: 1                   // Display order within category
}
```

Include ALL items from the research document tables (7 Pre-Contract, 14 Under Contract, 7 Closing = 28 items total). The linkedTemplateId values MUST match the documentTemplates Firestore IDs used in compliance.js seed data:
- "mo-purchase-agreement" (purchase_agreement item)
- "mo-listing-agreement" (listing_agreement item)

- "mo-hoa-addendum" (hoa_addendum item)
- "mo-sellers-disclosure" (sellers_disclosure item)
- "mo-buyer-rep-agreement" (buyer_rep_agreement item)

All other items have `linkedTemplateId: null` (non-doc milestone items).

**3. parseTransactionType(transactionType) function:**
Parses the combined transaction type string (e.g., "SFH - Buyer") into `{ propType, side }`:
```javascript
export function parseTransactionType(transactionType) {
  if (!transactionType) return { propType: null, side: null };
  const parts = transactionType.split(" - ");
  return { propType: parts[0]?.trim(), side: parts[1]?.trim()?.toLowerCase() };
}
```

**4. seedChecklist(db, clientId, transactionType, closingDate) async function:**
Seeds applicable checklist items to Firestore subcollection `clients/{clientId}/closingChecklist/{itemId}`.

Logic:
- Parse transaction type into propType and side using parseTransactionType
- Filter MO_CLOSING_CHECKLIST_TEMPLATE to items where:
  - `(item.transactionSide === side || item.transactionSide === "both")`
  - AND `item.propertyTypes.includes(propType)`
- Use `writeBatch(db)` with `batch.set(ref, data, { merge: true })` -- merge:true is CRITICAL for re-seeding (preserves existing completion state)
- Each doc written to `doc(db, "clients", clientId, "closingChecklist", item.id)` (deterministic ID)
- Document fields: `task, category, completed: false, autoCompleted: false, autoCompletedAt: null, notApplicable: false, notes: "", sortOrder, transactionSide, propertyTypes, linkedTemplateId, isCustom: false, isSeeded: true, deadlineOffsetDays, deadline: (computed from closingDate + offset or null), seededAt: serverTimestamp(), completedAt: null, completedBy: null`
- Deadline computation: if closingDate is a Firestore Timestamp, call `.toDate()` first. If closingDate exists and item.deadlineOffsetDays is not null, compute `new Date(closingDate.getTime() + item.deadlineOffsetDays * 86400000)`. Otherwise deadline = null.
- Import `writeBatch, doc, serverTimestamp` from Firebase Firestore CDN
- Import `db` from `./firebase-config.js`

**5. recalculateDeadlines(db, clientId, closingDate) async function:**
When closing date changes, batch-update all checklist items that have `deadlineOffsetDays != null`:
- Query all docs in `clients/{clientId}/closingChecklist`
- Filter those with `deadlineOffsetDays` field that is not null
- Use writeBatch to update each with new `deadline` value (closingDate + offset)
- If closingDate is null/undefined, set all deadlines to null

**6. Export all:** `MO_CLOSING_CHECKLIST_TEMPLATE, CHECKLIST_CATEGORIES, CATEGORY_LABELS, parseTransactionType, seedChecklist, recalculateDeadlines`
